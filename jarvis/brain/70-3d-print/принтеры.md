# Принтеры

Два принтера, две разные экосистемы. Ресурсы планировщика: `printer:bambu-p1s`, `printer:creality-k1`.

| | Bambu Lab P1S | Creality K1 |
|---|---|---|
| Область печати | 256 × 256 × 256 мм, закрытый корпус | 220 × 220 × 250 мм, закрытый корпус |
| Многоцветная печать | только с **AMS** (уточнить, есть ли) | нет (одноцветная; смена нити паузой M600) |
| Слайсер по умолчанию | Bambu Studio | Creality Print |
| Единый слайсер для JARVIS | **OrcaSlicer** — поддерживает оба, есть командная строка для нарезки | OrcaSlicer |
| Как JARVIS управляет | LAN-only Mode **+ Developer Mode** в настройках принтера → MQTT (статус, команды), FTP (загрузка 3MF). В облачном режиме сторонние команды заблокированы системой авторизации Bambu | Официальный **root-доступ** (настройки принтера) → Creality Helper Script → **Moonraker** REST/WebSocket (статус, загрузка G-code, старт печати) + Fluidd/Mainsail как веб-панель |
| Что нужно от владельца | включить LAN-only + Developer Mode, записать код доступа и серийник в `.env` | включить root, установить Moonraker через helper script (JARVIS подскажет шаги), IP в `.env` |
| Библиотеки | `bambulabs_api` / `pybambu` (Python, MQTT) | `moonraker-api` (Python) или прямой HTTP к `http://<ip>:7125` |

## Правила для обоих
- Физический старт печати — **только с подтверждения** (always-ask.md). Проверка параметров перед запуском: материал, температура, опоры, ориентация, время.
- «Модель проверена программно» ≠ «печать проверена». Формулировать точно.
- Двухцветный заказ (например, комбайн зелёный/чёрный): P1S + AMS — одним файлом; иначе разбить модель на детали по цветам и печатать раздельно (годится для обоих принтеров).
- Очередь: один заказ на принтер; второй принтер берёт следующий заказ, если материал/размер подходят.

## Открытые вопросы
- Есть ли AMS у P1S?
- K1 уже с root и Moonraker или стоковая прошивка?
- Оба принтера в одной Wi-Fi-сети с ПК? (нужно для LAN-управления)
