# Архитектура (кратко)

Полная версия с диаграммами — [`../PLAN.md`](../PLAN.md) §3. Аудит существующего — [`../AUDIT.md`](../AUDIT.md).

## Слои
1. **Каналы**: Telegram (голос/текст/фото), окно OpenJarvis на ПК, микрофон (этап 7).
2. **Шлюз** (облако, всегда включён): Vercel-вебхук → Supabase (`core/gateway/schema.sql`).
3. **Локальный агент** (Windows): забирает очередь, исполняет, отчитывается.
4. **Слой политики** (`core/jarviscore/policy.py`, хуки Claude Code): allow-list папок и программ, ASK/DENY по командам, журнал.
5. **Оркестратор** = Claude Code с `CLAUDE.md` этого репозитория + субагенты `.claude/agents/`.
6. **Планировщик** (`core/jarviscore/planner.py`): приоритеты, дедлайны, зависимости, ресурсы, пауза/восстановление.
7. **Раннер** (`core/jarviscore/claude_runner.py`): `claude -p` по подписке, сессии, учёт расходов, стоп-кран.
8. **Память**: `brain/` (Obsidian) + индекс OpenJarvis; правила трёх уровней.
9. **Интеграции** (этап 6): CRM (Supabase), Metricool, Higgsfield, 3ds Max MCP, Bambu Studio/MQTT, Playwright.

## Инварианты
- Ничего не считается сделанным без независимой проверки и артефакта.
- Локальные действия не обещаются, когда ПК недоступен.
- Секреты не покидают `.env`/Диспетчер учётных данных.
- Каждое действие инструмента — строка в `data/logs/actions.jsonl`.
