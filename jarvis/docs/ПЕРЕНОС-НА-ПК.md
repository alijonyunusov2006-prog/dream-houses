# Перенос JARVIS на компьютер владельца

Решение владельца (2026-10-03): **всё работает у него локально.** Пока JARVIS готовится в GitHub.
Перенос начинается, когда владелец скажет одно из двух:

- **«HDD пришёл, место освободил»** — JARVIS ставится на SSD (C:) текущего ПК «Alijon». Сначала `sysadmin` делает аудит и
  переносит ненужное на HDD (D:) по правилу удаления и с подтверждением. На SSD держим не меньше 50 ГБ свободными.
- **«Купил ноутбук, переноси»** — владелец входит в свой аккаунт на ноутбуке, JARVIS ставится туда. Настройки машины —
  новый файл `config/machines/<имя ноутбука>.toml` по образцу `_laptop.example.toml`.

## Порядок (одинаковый для ПК и ноутбука)
1. Перенести папку `jarvis/` в **приватный** репозиторий с историей. Сейчас `dream-houses` публичный, а в мозге личные данные. Без этого шага не начинать.
2. Установщик `Установить-Jarvis.bat`: Python, Git, сборка, OpenJarvis, ярлык, автозапуск, язык Claude Code — русский.
3. Склонировать приватный репозиторий в `C:\jarvis`.
4. Секреты на ПК: `DHOS_AGENT_KEY` (ключ DH OS выдаёт владелец), токен бота JARVIS, chat_id владельца.
5. Telegram: **свой бот JARVIS** для связи с владельцем; задачи сотрудникам — через бот DH OS.
6. Инструменты: Obsidian (открыть `C:\jarvis\brain` как хранилище) + плагин MCP Tools, Graphify (`pip install graphifyy`, затем `/graphify brain`),
   3dsmax-mcp и навык 3dsmax-rendering. Подключить их в Claude Desktop, чтобы ваш Claude видел мозг и навыки JARVIS.
7. Голос: `core/scripts/voice_samples.py` → владелец выбирает голос или делает копию своего.
8. Проверка: тесты ядра, отчёт в Telegram, чтение задач из DH OS, 3D-офис с живыми данными. Только после этого — «готово».

## Что не забыть
- Модели ИИ и голоса — на SSD, не на HDD (HDD только для холодного архива).
- После переноса на ноутбук старый ПК может остаться исполнителем рендеров и печати — очередь одна.
