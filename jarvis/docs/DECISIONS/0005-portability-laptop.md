# ADR-0005. JARVIS переносим: одна папка, любой компьютер

**Дата:** 2026-09-28 · **Статус:** принято

## Контекст
Владелец планирует купить ноутбук и хочет скопировать JARVIS с ПК на него так, чтобы всё работало,
включая память (brain) и навыки. Одновременно C: ПК почти полон.

## Решение
1. **Всё, что делает JARVIS JARVIS-ом, лежит в одной папке `C:\jarvis`** — репозиторий Git: код, агенты,
   навыки, `brain/`, конфиги. Ничего из этого не разбросано по системе.
2. **Что не копируется, а ставится заново** установщиком (`Установить-Jarvis.bat` + этап 3): Python, Git, Rust,
   Ollama и модели, whisper/TTS-модели, OpenJarvis, Everything. Они большие и машинно-зависимые.
3. **Секреты** (`.env`, Диспетчер учётных данных) не копируются автоматически — переносятся вручную один раз.
4. **Память общая через Git**: brain/ коммитится и синхронизируется (приватный репозиторий). `sysadmin`
   делает `git pull` при старте и `git push` после изменений; конфликты решаются в пользу более новой записи,
   спорное — вопрос владельцу.
5. **Настройки машины** — `config/machines/<COMPUTERNAME>.toml` (пути, наличие GPU, принтеров, программ);
   общие настройки — `config/settings.toml`. Код читает общие, потом накладывает машинные.
6. **Очередь задач одна** (Supabase). Локальный агент каждой машины шлёт пульс со своим именем; задача
   исполняется тем ПК, который включён и подходит по ресурсам (рендер — там, где RTX 3090).
7. Никаких абсолютных путей в коде и навыках, кроме `config/`. Путь к проектам, архиву, моделям — из настроек.

## Последствия
+ Переезд = `git clone` + установщик + `.env`. Ноутбук и ПК видят один и тот же brain.
− Нужен приватный репозиторий на GitHub (или другой Git-хостинг) и дисциплина синхронизации — берёт на себя `sysadmin`.
