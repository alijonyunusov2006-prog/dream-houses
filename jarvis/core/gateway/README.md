# Шлюз (облачная часть) — этап 3

Назначение: принимать задания из Telegram **всегда**, даже когда ПК выключен, и хранить очередь.

```
Telegram → вебхук (Vercel, Python-функция) → Supabase (схема jarvis) ← локальный агент (ПК) → Telegram (ответы)
```

- `schema.sql` — таблицы `messages`, `tasks`, `events`, `agent_heartbeat`. Защита от повторов —
  уникальность `(chat_id, telegram_id)`.
- Вебхук принимает только сообщения от `OWNER_CHAT_ID` (остальное — в журнал и игнор), пишет запись в
  `messages`, для голосовых сохраняет `file_id` (скачивает и расшифровывает локальный агент, у которого есть GPU).
- Если `agent_heartbeat.last_seen` старше 2 минут, вебхук сразу отвечает: «Принял. ПК сейчас недоступен —
  задача в очереди, выполню при включении». Никаких обещаний выполнить локальное действие.
- Локальный агент раз в 5–10 с забирает `handled = false`, обновляет пульс, ведёт `tasks`, пишет `events`,
  отвечает в Telegram напрямую (Bot API).
- Переменные: `TELEGRAM_BOT_TOKEN`, `OWNER_CHAT_ID`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` — в Vercel и в `.env` на ПК.

Код вебхука и локального агента появляется на этапе 3 вместе с тестами; здесь — только контракт данных.
