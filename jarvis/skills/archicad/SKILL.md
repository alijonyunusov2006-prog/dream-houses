# Назначение
Дать агенту `archicad` возможность строить и править планировки в **Archicad** на ПК владельца,
чтобы задача «фото плана + размеры → планировка в Archicad» выполнялась без человека за клавиатурой.
Владелец сам в Archicad не работает — агент должен уметь всё сам и отчитываться скриншотами и данными модели.

# Необходимые инструменты (ставятся один раз на ПК)
1. **Archicad 25–29** (Windows). Версия на ПК владельца — уточняется (`brain/00-inbox/questions.md`).
2. **Tapir Archicad Add-On** (MIT) — добавляет в Archicad десятки JSON-команд, включая создание элементов.
   Скачать `.apx` под свою версию: https://github.com/ENZYME-APD/tapir-archicad-automation/releases →
   Archicad → *Options → Add-On Manager* → добавить файл. Документация команд:
   https://enzyme-apd.github.io/tapir-archicad-automation/archicad-addon/
3. **MCP-сервер** поверх Tapir и официального API. Основной вариант — `tapir-archicad-MCP`
   (MIT, 191+ инструментов, Python 3.12+, `uv`): https://github.com/SzamosiMate/tapir-archicad-MCP
   Подключение к Claude Code (в папке `jarvis/`):
   ```
   claude mcp add ArchicadTapir -- uvx --from tapir-archicad-mcp archicad-server
   ```
   Для Claude Desktop — блок в `%APPDATA%\Claude\claude_desktop_config.json`:
   ```json
   {"mcpServers": {"ArchicadTapir": {"command": "uvx", "args": ["--from", "tapir-archicad-mcp", "archicad-server"]}}}
   ```
   Альтернатива для Archicad 29 — `alesdev88/Archicad-MCP` (40+ кураторских инструментов + QA-проверки;
   `claude mcp add archicad -- archicad-mcp --mode full`). Известное ограничение: чтение свойств элементов
   может ронять Archicad 29 — **сохранять проект перед чтением свойств**.
4. Для запасного пути — Python-пакеты `ifcopenshell` (IFC) и `ezdxf` (DXF).

# Инструкции
Общие правила (те же, что для Revit, они проверены практикой):
1. **Сначала читай, потом пиши.** Получи список этажей (stories), единицы измерения, выбранные элементы,
   границы проекта. Модель «живая» — не строй вслепую.
2. **Единицы и этаж.** Archicad работает в метрах в API; размеры владельца — в мм/см. Переводи явно и
   фиксируй в отчёте. Каждый элемент — на конкретном этаже.
3. **Дроби задачу.** «Построй квартиру» — плохой единичный запрос. Порядок: этажи → наружные стены по
   осям → перегородки → двери/окна → зоны (помещения) → размеры/маркировка → 2D-вид/скриншот.
4. **Геометрия явно.** Координаты, длины, толщины, тип элемента. Чем конкретнее — тем выше шанс с первого раза.
5. **Проверяй после каждого шага.** Перечитай созданные элементы через API; не считай команду выполненной,
   пока не увидел результат в данных. Не получилось — скажи честно и предложи запасной путь.
6. **Специализированный инструмент важнее «выполни код».** Произвольный код — крайняя мера.

Сценарий «планировка из фото»:
1. Фото/PDF плана + размеры от владельца → разметка помещений и стен (список: имя, координаты углов,
   толщины, проёмы) в `brain/30-projects/<проект>/планировка.md`. Неясные размеры — вопрос, ≤ 5 штук.
2. Проверка эргономики скиллом `apartment-planner` (проходы, минимальные размеры) — до построения.
3. Построение в Archicad по шагам из п. 3 выше; после каждого блока — чтение элементов и скриншот.
4. Экспорт: PLN сохранён, плюс PDF плана и, если нужно инженерам, IFC/DWG.
5. Отчёт по форме JARVIS: что построено (список элементов с количествами), как проверено (данные API +
   скриншоты), что не удалось, файлы.

Запасные пути (по убыванию предпочтения):
- **IFC/DXF без Archicad**: сгенерировать геометрию `ifcopenshell`/`ezdxf` и импортировать в Archicad —
  когда MCP недоступен или команды не покрывают нужный элемент.
- **Управление интерфейсом** (скриншот + мышь/клавиатура, computer-use) — только для действий, которых нет
  в API (диалоги публикации, настройки), с обязательным скриншотом «до/после».

# Ограничения и разрешения
- Работать на **копии** файла проекта; перед массовыми операциями — сохранить и сделать бэкап (`.pln` + дата).
- Массовое удаление, замена библиотек, изменение настроек проекта — только с подтверждения (always-ask.md).
- Не заявлять «построено», если элементы не перечитаны из модели.

# Условия успешного завершения
- Все помещения из ТЗ есть в модели как зоны с верными площадями (±2 %).
- Стены/проёмы соответствуют списку из `планировка.md`; скриншот плана приложен.
- Файл открывается в Archicad без ошибок; PDF плана сформирован.
