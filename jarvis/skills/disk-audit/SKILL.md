# Назначение
Освободить C: (SSD, 1,86 ТБ, свободно ≈ 80 ГБ), когда придёт HDD (≈ через 10 дней от 2026-09-28),
разложить файлы по понятной структуре и сделать так, чтобы JARVIS находил любой файл за секунды.

# Необходимые инструменты
- PowerShell 5.1+ (есть в Windows). Скрипт аудита: `core/scripts/Disk-Audit.ps1`.
- **Everything** (voidtools, бесплатно) + `es.exe` (Everything CLI) — мгновенный поиск по имени/размеру/дате на NTFS.
  Установка: `winget install voidtools.Everything` и `winget install voidtools.Everything.Cli` (с подтверждения владельца).
- Опционально: WinDirStat/WizTree для картинки владельцу (не обязательно, отчёт скрипта достаточен).

# Инструкции

## 1. Аудит (ничего не удаляем)
```
powershell -ExecutionPolicy Bypass -File core/scripts/Disk-Audit.ps1 -Roots C:\ -MinFileMB 500 -TopN 60
```
Скрипт пишет в `data/reports/disk-audit-<дата>.md` и `.json`: свободное место по дискам, размеры папок
верхних уровней, самые большие файлы, размеры известных кэшей/temp, сводку по расширениям.

## 2. Четыре корзины
| Корзина | Что туда попадает | Действие |
|---|---|---|
| Мусор | `%TEMP%`, `C:\Windows\Temp`, кэши браузеров и пакетов (pip/npm/uv), `Windows.old`, старые установщики `.exe/.msi` в Загрузках, autobackup 3ds Max старше 30 дней, корзина | удалить **после подтверждения**; сначала в корзину, окончательно через 7 дней |
| Перенести на D: | рендеры (`.png/.exr/.tif` из папок рендеров), видео, архивы закрытых проектов, модели ИИ (Ollama `~/.ollama/models`, whisper, TTS), библиотеки 3D (мебель, текстуры), дистрибутивы | переместить по стандарту папок ниже; для моделей Ollama — переменная `OLLAMA_MODELS=D:\AI\ollama` |
| Оставить на C: | программы, активные проекты, `C:\jarvis`, `C:\Projects`, профиль пользователя | — |
| Спросить | большие файлы непонятного назначения, дубликаты, чужие проекты | список владельцу с путями и датами |

## 3. Стандарт папок на D:
```
D:\
├── Projects\      активные проекты студии: ГГГГ-ММ_Клиент_Объект\ (чертежи, рендеры, документы внутри)
├── Archive\       закрытые проекты по годам: 2024\, 2025\ …
├── Renders\       готовые рендеры по проектам (если не внутри проекта)
├── 3D\            Models\ (свои модели) · Print\ (STL/3MF, заказы) · Library\ (мебель, текстуры, HDRI)
├── Media\         Photo\ · Video\ · Content\ (Instagram: готовые публикации по датам)
├── Docs\          договоры, КП, сметы, шаблоны
├── AI\            ollama\ · whisper\ · tts\ (модели ИИ)
├── Software\      дистрибутивы и установщики
└── Backup\        бэкапы brain/, проектов, CRM (ежедневно, режим «Ночь»)
```
Имена: без пробелов и кириллицы в системных папках (`AI`, `Software`), в проектах кириллица допустима:
`2026-09_Иванов_Квартира-3к`. Дата всегда впереди — сортируется сама.

## 4. Перенос
- Только по утверждённому плану, папками, с проверкой контрольной суммы для проектов (`robocopy /MIR /COPY:DAT /R:1` + сверка количества и размера файлов).
- Программы, которые ждут файлы по старому пути (3ds Max библиотеки, Ollama), перенастроить и проверить запуск.
- Каждое перемещение — строка в `data/logs/actions.jsonl`; итог — отчёт «что → куда, сколько освободилось».

## 5. Поиск файлов
- Everything индексирует все NTFS-диски мгновенно. Запросы: `es.exe -sort size -n 10 "*.max"`,
  `es.exe dm:thismonth ext:pln`, `es.exe "Иванов" ext:pdf`.
- Карта «где что лежит» — `brain/20-me/файлы.md`: JARVIS обновляет после каждого переноса; при вопросе
  владельца «где файл X» — сначала Everything, затем карта, ответ с путём и датой.

# Ограничения и разрешения
- Удаление и перенос — только после подтверждения владельца по корзинам (always-ask.md).
- Не трогать `C:\Windows`, `Program Files`, `ProgramData`, профили других пользователей, скрытые системные файлы (`pagefile.sys`, `hiberfil.sys`).
- Не запускать дефрагментацию/очистку SSD-инструментами третьих сторон.

# Условия успешного завершения
- На C: свободно ≥ 300 ГБ (цель) и не меньше 50 ГБ (минимум) — цифра из отчёта до/после.
- Все перенесённые проекты открываются из нового места; программы запускаются.
- Everything установлен, `es.exe` находит тестовый файл; `brain/20-me/файлы.md` заполнена.

# Тесты
`tests/01-audit-report.md` — отчёт формируется на тестовой папке; `tests/02-poisk.md` — поиск файла.

# Статус
Скрипт аудита проверен на тестовой папке в Linux (pwsh); на Windows-ПК владельца — ещё нет.
